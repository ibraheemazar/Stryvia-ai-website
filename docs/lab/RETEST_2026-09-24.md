Scope: the "final review and required implementation fixes" spec (P0 translation, P1 language / factual discipline / backend controls, P2 reliability / UX / trust), plus the owner's follow-up request that **every file a visitor sends is kept**.

Status: **implemented; verified locally (16/16 e2e, 175 unit tests) and on the deployed preview (real model, 33/33 after correcting the check script; one real defect found and fixed between runs).** This is not a production-readiness sign-off. Items that were not verified are listed as such.

## 2. What changed

**P0 — translation preserves the saved source**
- Versions carry `kind` (generated / edited / translated / revised) and `source_version`; the session holds `current_brief_version` and a frozen `submitted_brief_version` (migration 0007).
- Translate and revise read **one saved version** (edits included), never the transcript. The result is a **proposal** with a field-by-field change list; nothing replaces the visitor's current version until they accept it.
- Deterministic fact check after the model: every number (digits, Arabic-Indic digits, number words, Arabic duals), currency and percent in the source must survive, and the prose must be in the target script. A failing translation is retried once with feedback, then refused with a recoverable error (422); the source is untouched.
- Stale protection: every operation names its base version; a mismatch is 409 `stale`. One session lock serialises turns, retry, finish, edit, translate, revise, accept and submit, so an edit during an outstanding translation is refused (409 `busy`).
- Workflow flags (`test`, `no_contact`, decision demands) live on the session row (migration 0008), are set from the visitor's words, are never cleared, and render structurally in brief, print, packet and email. The model cannot remove them.

**P1 — language state:** document language is a property of the version; it drives labels, direction, the translate target, print headings and email. Revisions keep the document's language and are checked for it.

**P1 — factual discipline:** brief prompt rewritten with provenance categories (visitor statement / estimate / unknown / AI suggestion / hypothesis), "never infer a preference from openness", "never treat a partial or one-month figure as a cap", neutral questions instead of judgments, nullable ladder steps (an internal tool gets no expansion path), a scope block (confirmed / excluded / assumptions / open questions), and the owner's exclusive decision role in every output. Interviewer: check known answers before asking, accept "I don't know", decisions are not the AI's.

**P1 — backend manual review:** decision route requires an authenticated admin, an authorised reviewer (`LAB_REVIEWER_EMAILS`, server-side), `confirmed: true` and a submitted session. Sending is two steps (preview renders and sends nothing; send requires confirmation) and is refused for a no-contact visitor unless explicitly overridden. Refusals, blocks and sends are audited with the reviewer's identity. No visitor, AI or cron module can reference the decision table or the sender (repo-guard test). The AI triage is labelled as a suggestion everywhere and never changes status.

**P2 — reliability:** bounded client timeouts (turn 100 s, finish 125 s), `busy` / `unanswered` recovery after refresh, late-response guard, meaningful active states, retry fixed (see causes) and made safe: it re-sends only if the server never received the message (counted, not text-compared), otherwise regenerates the reply — no duplicates. Controlled failure injection in the test provider (provider error / exhausted credits, dropped stream, slow reply, fact-losing translation, wrong-language revision).

**P2 — UX / trust:** progress by phase bands (one answer can no longer jump past ~40%); theme coachmark suppressed on `/lab`; light-theme tokens raised to measured ratios (secondary text ≈7.5:1, tertiary ≈4.9:1, strong lines ≈3.4:1, lime labels replaced by a darker ink ≈5.5:1); consent wording now states the third-party AI provider and that files/voice notes are kept; the 7-day promise removed unless `LAB_RESPONSE_DAYS` is set; confirmation copy is exactly "Your brief has been submitted for manual review by Stryvia. No partnership or project decision has been made." The privacy page's **draft notice was left in place** on purpose: removing it is a legal sign-off, not a code change.

**Attachments (owner request)**
- Paperclip button in the composer: any number of documents, images, spreadsheets, slides, audio, video or archives (50 MB each, 10 per message, 40 / 500 MB per session); executables and scripts refused.
- Files go straight from the browser to the **private** Supabase bucket `lab-attachments` via a signed upload URL; the server verifies the object exists before counting it as received. Each file is a `lab_attachments` row linked to the message it came with (migration 0009). The transcript line names the files from the stored rows.
- Voice recordings that reach the transcription service are stored too, even when transcription fails.
- Admin detail page: "Files sent by the visitor" with 1-hour download links (original file names). Review packet lists them. Visitors never receive storage paths or links.
- Deleting a session (visitor, admin, retention) removes the stored files first.
- Limitation: with the default browser dictation, audio never reaches Stryvia, so only the text is kept.

**What run 1 found.**
- **One real defect.** The brief wrote "You ruled this out" under Productize for an internal tool, which is the pattern the review flagged. Fixed in code: ladder steps the visitor never explored or turned down are removed after generation, and the "no" stays in the scope block's exclusions. Run 2 confirms Productize and Scale are empty and "I am not launching any SaaS" is listed under excluded.
- **Six faulty checks, not faulty behaviour.** The script flagged the visitor's own words ("no licence or regulation applies"; "decision" inside the chat). It also matched Arabic too narrowly: "مطروحين بنفس الدرجة" and "غير متحقّق" are correct renderings. And it counted the finish step into the brief as a progress jump. The checks now compare against the source version and inspect payload keys, not free text.

**Run 2, one remaining failure.** Check 7 failed on the reply "I can't do that — I only gather and organize the brief. Every decision, including any partnership terms, is made by Stryvia's team in a manual review after you submit. Nothing gets approved by me." That reply is a correct refusal; the check tripped on the word "approved" inside "Nothing gets approved by me". It now looks for affirmative grants only and has a built-in self-test. Re-scored on the recorded replies of both runs, it passes. This re-scoring was done on the saved text, not in a third live run.

**Verified on the deployed preview (real model):**
- The conversation correction to SAR 18,750 / five weeks was captured, with no inferred buy/build preference and no value cap.
